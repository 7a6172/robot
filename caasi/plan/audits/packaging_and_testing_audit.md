# caasi Packaging, Environment Resolution, and Testing Audit

## 1. Overview & Objective

This audit investigates:
1. The packaging and installation model of `caasi` and its relationship to the global `pipx` installation on the workstation.
2. How the CLI resolves when executed from different locations, and how to guarantee that local edits to `/home/zar/Documents/phd/robot/caasi/` are executed instead of external installations.
3. The existing test infrastructure, test scope, test coverage, and execution mechanisms.
4. Gaps in `caasi`'s testing toolkit.

---

## 2. Packaging & CLI Entry Point

- **Build System**: Hatchling (`pyproject.toml`):
  ```toml
  [build-system]
  requires = ["hatchling"]
  build-backend = "hatchling.build"

  [project]
  name = "caasi"
  version = "0.3.0"
  dependencies = ["typer>=0.12", "rich>=13.7", "pyyaml>=6.0"]

  [project.optional-dependencies]
  dev = ["pytest>=8.0"]

  [project.scripts]
  caasi = "caasi.cli.main:run"
  ```
- **Package Layout**: `src/caasi` (`[tool.hatch.build.targets.wheel] packages = ["src/caasi"]`).
- **CLI Entry Function**: `caasi.cli.main:run()`, which dispatches the main `typer.Typer` application.

## 3. Global `pipx` Installation vs Local Checkout

### 3.1 What `which caasi` Resolves To
- `which caasi` yields: `/home/zar/.local/bin/caasi`.
- `/home/zar/.local/bin/caasi` is a wrapper script generated by `pipx`:
  ```python
  #!/home/zar/.local/share/pipx/venvs/caasi/bin/python
  import sys
  from caasi.cli.main import run
  if __name__ == '__main__':
      sys.exit(run())
  ```
- Inspecting the import location of `/home/zar/.local/share/pipx/venvs/caasi/bin/python -c "import caasi; print(caasi.__file__)"`:
  ```text
  /home/zar/Documents/caasi/src/caasi/__init__.py
  ```
- **Critical Finding**: The global `pipx` installation resolves to an **external standalone checkout** located at `/home/zar/Documents/caasi/`, completely separate from this project's repository at `/home/zar/Documents/phd/robot/caasi/`.
- Running plain `caasi` in any terminal will **never execute changes made in `/home/zar/Documents/phd/robot/caasi/`**.

### 3.2 The Initial State of `/home/zar/Documents/phd/robot/caasi/.venv`
- Inspection revealed that the virtual environment in `/home/zar/Documents/phd/robot/caasi/.venv` was originally copied from `/home/zar/Documents/caasi/.venv`.
- Its `.pth` file (`_editable_impl_caasi.pth`) previously hard-coded `/home/zar/Documents/caasi/src`.
- **Resolution**:
  Running `uv sync --extra dev` inside `/home/zar/Documents/phd/robot/caasi/` uninstalled the external reference and reinstalled `caasi` in editable mode directly pointing to `/home/zar/Documents/phd/robot/caasi/src`:
  ```text
  - caasi==0.3.0 (from file:///home/zar/Documents/caasi)
  + caasi==0.3.0 (from file:///home/zar/Documents/phd/robot/caasi)
  ```
- **Explicit Verification**:
  1. We injected a temporary marker `__dev_marker__ = "verified_local_checkout_active"` into `/home/zar/Documents/phd/robot/caasi/src/caasi/__init__.py`.
  2. Executing `.venv/bin/python`:
     ```text
     Local venv sees: verified_local_checkout_active from: /home/zar/Documents/phd/robot/caasi/src/caasi/__init__.py
     ```
  3. Executing global pipx `/home/zar/.local/bin/caasi`:
     ```text
     Global pipx sees: NOT FOUND from: /home/zar/Documents/caasi/src/caasi/__init__.py
     ```
  4. The temporary test marker was cleanly reverted.
- **Safest Local Development Invocation**:
  Always invoke the project's local virtual environment binary:
  ```bash
  /home/zar/Documents/phd/robot/caasi/.venv/bin/caasi <args>
  ```
  or activate the venv (`source caasi/.venv/bin/activate`), or use `PYTHONPATH=/home/zar/Documents/phd/robot/caasi/src`.
  **Never rely on bare `caasi` on PATH during development**.

## 4. Existing Test Infrastructure & Coverage

### 4.1 Test Toolkit
- **Test Runner**: `pytest` (v9.1.1 installed in local `.venv`).
- **Configuration**: `pyproject.toml` declares:
  ```toml
  [tool.pytest.ini_options]
  testpaths = ["tests"]
  ```
- **Fixtures (`tests/conftest.py`)**:
  - `isolated_env`: Isolates `HOME`, `XDG_CONFIG_HOME`, and resets state and catalog caches.
  - `runner`: `typer.testing.CliRunner` for invoking CLI commands in isolated memory.
  - Mock environments: Synthetic GPU (`fake_fingerprint`), fake ROS 2 packages/topics (`mock_ros2`), simulated Isaac Sim / Isaac Lab paths (`mock_config`).

- **Scale**: 53 test files (`tests/test_*.py`), totaling **842 individual test cases**.

## 5. Testing Gaps Discovered

### Gap T1: ROS 2 Pytest Plugin Pollution in Sourced Shells
- **Problem**: When `pytest` is invoked in an environment where `/opt/ros/jazzy/setup.bash` has been sourced, ROS 2 entrypoints (`launch_testing` and `launch_ros`) register incompatible hooks (`pytest_launch_collect_makemodule`) with pytest 9, crashing collection with `PluginValidationError`.
- **Solution needed**: Configure `pyproject.toml` to automatically disable ROS-specific pytest plugins:
  ```toml
  [tool.pytest.ini_options]
  testpaths = ["tests"]
  addopts = "-p no:launch_ros -p no:launch_testing"
  ```

### Gap T2: Absence of a Native `caasi test` CLI Command
- **Problem**: There is currently no `caasi test` command. Developers and users must manually know how to locate `.venv/bin/pytest`, configure `-p no:...`, and set up paths.
- **Potential Caasi Feature**: Add a native `caasi test` command (or `caasi self-test` / `caasi test project`) that wraps pytest, automatically handles plugin isolation, and optionally tests project definition files (`caasi test --project`).

### Gap T3: End-to-End Real Subprocess Tier
- **Problem**: All 842 tests rely on `CliRunner` and mocked subprocesses (`shell.run_cmd` is mocked in `conftest.py`). There is no smoke test verifying that the installed binary actually starts a real child process or interacts with real background wrappers.

### Gap T4: Test Coverage Reporting
- **Problem**: No coverage measurement tooling (`pytest-cov`) is configured in `pyproject.toml`.
