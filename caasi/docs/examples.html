Caasi v0.4.0 Runnable examples, and where to find a real one for any command

Examples & Command Index

The repository ships a catalog of runnable examples — real caasi projects, not snippets. If you want to know how to use caasi X, this is where the smallest real example lives.

Find a command's example two ways:
  • the command index below maps command families to examples;
  • examples/COVERAGE.md is the auditable matrix — every command in the CLI, mapped to its example and validation tier.

Suggested order for a new user: 01 → 02 → then 03 or 04 → then 07. Examples 05 and 06 need a display or a GPU and are best left until the basics are clear.

What the validation tiers mean

TierMeaning
CIRun automatically by the test suite. If it breaks, the build fails.
opt-inRun when the prerequisite exists, and skipped automatically when it does not. Never claimed as validated when it was not run.
manualNeeds a display, a terminal, or hardware. Documented with its prerequisites rather than presented as covered.

How the examples treat the ecosystem

Each example states which parts caasi contributes and which belong to the underlying tool. The catalog references canonical upstream examples rather than duplicating them:

ExampleThe ecosystem providesCaasi provides
03demo_nodes_py — the canonical ROS 2 talker/listenerThe project, the target context, the observation commands, the provenance
04The Docker runtime, images and container lifecycleObservation through the container CLI, and a reason when none is installed
05turtlesim, rviz2, rqt, ros2 bagTarget context so a local GUI can attach to a remote graph
06Isaac Sim, the Isaac Lab tasks and its training entry pointRequirements, GPU-aware target selection, run tracking
01Your program (deliberately trivial)Everything around it: the workflow being taught
No example moves hardware, deletes data, or invents safety flags. teleop start/record, nav launch, moveit launch, motion execute, run delete, project remove and setup are documented but never executed — and neither of the destructive pair has a --dry-run, so there is no safe demonstration to fake. A test enforces this.
