1. openmover_msgs interfaces

Pure rosidl interface package. 8 message + 10 service definitions, field-identical to ROS 1 (only CamelCase/type-syntax renames were needed). Service files were flattened out of their ROS 1 subfolders because ROS 2 requires a flat srv/ directory.

MessagesBmsData, FlowState, MotorState, NavToSimple, NavToState, Obstacle, Pose, Twist
ServicesCmdVelModeRequest, DirectRequest, FlowAction, FlowCmd, NavToRequest, NavToSimpleRequest, PlaysoundRequest, SelfTestReportRequest, StopRequest, WorkModeRequest

3. auto_mapping_toolbox (+ msgs) algorithm

Frontier-based autonomous mapping. auto_mapping_handler runs a 7-state machine, uses boost R-tree spatial queries, its own nav2_costmap_2d costmap, Dijkstra expansion, and an OSQP path smoother. Provides global + local exploration, collision prediction, and TSP ordering of frontier goals.

Interfaces: AutoMappingState.msg, AutoMappingRequest.srv. Built with default optimization; config in config/config.yaml.

4. relocalization_toolbox (+ msgs) algorithm

Global 2D relocalization using a likelihood-field score plus PCL GICP scan matching, with RRT/reachability sampling of candidate poses. relocalization_2d_handler exposes relocalization and initial-pose services.

Interfaces: InitialPoseRequest.srv, RelocalizationRequest.srv. Built with -O3 -flto -ffast-math -funroll-loops (scoring/sampling are compute hot-spots) — restored to match ROS 1 during the audit. Config in config/config_2d.yaml.

5. bluesea2 driver

Lanhai (BlueSea) 2D LiDAR driver, a ROS 2 port supporting UDP transport, angle filtering, inversion, and configurable scan topic/frame. The bring-up parameters (UDP, LiDAR IPs 192.168.100.101/.102, ports 6667/6668, ±1.57 rad filter) are inlined in openmover/launch/hardwares/bringup.launch.py with full ROS 1 parity, publishing openmover/hardware/lidar_forward/scan and openmover/hardware/lidar_rear/scan.

Note

This is a manually completed ROS 2 port, not the vendor's official driver as originally planned — see the audit.

6. ira_laser_tools perception

laserscan_multi_merger merges the two LiDAR scans into a single 360° scan on frame lidar_link (openmover/hardware/lidar/scan) plus a PointCloud2. The ROS 1 laserscan_virtualizer was never used by bring-up and was not carried over. dynamic_reconfigure was replaced with declared parameters.
