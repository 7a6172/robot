Build Guide

How to build, rebuild and test the workspace on any machine. The only machine-specific decision is the build parallelism, which depends on your RAM — pick your tier below, or let tools/setup.sh pick it for you.

1. Choose your parallelism tier

The C++ packages here (costmaps, planners, relocalization) are memory-hungry translation units. Compiler parallelism must be sized to RAM or the kernel's OOM handling will freeze the machine:

RAMBuild flagsNotes
≥ 32 GB --parallel-workers $(nproc)
no MAKEFLAGS cap needed		 Full parallel build is safe.
16–31 GB MAKEFLAGS="-j2" CMAKE_BUILD_PARALLEL_LEVEL=2
--parallel-workers 2		 The proven setting — full parallelism has hard-frozen 16 GB hosts during development.
8–15 GB MAKEFLAGS="-j1" CMAKE_BUILD_PARALLEL_LEVEL=1
--parallel-workers 1		 Build works; run Gazebo only with headless:=true and close everything else.
< 8 GB — Not recommended: the simulation itself needs ~10 GB together with RViz.
Automatic

bash tools/setup.sh reads /proc/meminfo, proposes the matching tier, and lets you override it before building.

2. Build the workspace

From the workspace root (the directory containing src/):

# source ROS first
source /opt/ros/jazzy/setup.bash

# example for a 16 GB host — substitute your tier's flags
MAKEFLAGS="-j2" CMAKE_BUILD_PARALLEL_LEVEL=2 \
    colcon build --symlink-install --parallel-workers 2

# activate the workspace in this shell (also add to ~/.bashrc)
source install/setup.bash

Build a single package (and its dependencies) instead of everything:

colcon build --symlink-install --packages-up-to warehouse_simulation

3. What symlink-install means

--symlink-install installs interpreted files (YAML configs, launch files, URDF, Python scripts) as symlinks instead of copies. Editing them in src/ takes effect immediately — no rebuild needed. This is how runtime configs under src/openmover/config_defaults/ stay live-editable.

4. Rebuilding

You changed…Action
YAML / launch / URDF / Python scriptsNothing — symlinked (see above)
C/C++ sources or headerscolcon build --packages-select <pkg>
CMakeLists.txt flags or package.xml colcon build --packages-select <pkg> --cmake-clean-cache
Everything (fresh start) rm -rf build install log then the full build command. Only src/ and tools/ are needed to rebuild.

5. Testing

The workspace ships tests for the simulation package (bridge config, world file, launch sanity):

colcon test --packages-select warehouse_simulation
colcon test-result --verbose

A full simulation smoke test is described in Usage.

Troubleshooting

SymptomCause / fix
Machine freezes during build Too much parallelism for your RAM. Reboot, drop one tier (table above), rebuild.
colcon: command not found sudo apt install python3-colcon-common-extensions, and make sure /opt/ros/jazzy/setup.bash is sourced.
CMake cannot find osqp OSQP is not in Ubuntu 24.04 apt. Build it from tools/osqp_build (Getting Started, step 5) or run sudo bash tools/install_deps.sh.
Package stops finding a renamed/added dependency Delete that package's build/<pkg> folder and rebuild with --cmake-clean-cache.
Gazebo fails to start after a crash Stale session: pkill -f "gz sim"; pkill -f ruby, then retry (see Usage).
