Hardware

Recommended development/simulation host requirements, the memory rules that shape every build and run command, and the real-robot hardware (LiDARs, motor controller, IO board) with its network layout.

Development / simulation host requirements

ComponentRequirement
OSUbuntu 24.04 LTS (required by ROS 2 Jazzy binaries)
CPUx86_64 multi-core (4 cores or more recommended)
RAM16 GB recommended; 8 GB is the practical minimum (see the Build guide tiers)
GPUAny OpenGL 3.3+ GPU for the Gazebo GUI; none needed for headless runs
Disk ~10 GB for ROS 2 + Gazebo, ~3 GB for workspace artifacts

The migration was developed and validated on an Intel i7-12700K / 16 GB DDR5 / NVIDIA RTX 3080 machine running Ubuntu 24.04 — the build settings recommended throughout this documentation are the ones proven on that reference configuration.

Memory & parallelism

A fully parallel colcon build can exhaust memory on 16 GB hosts and hard-freeze the system. Therefore:

  • Match compiler jobs to RAM — 32 GB+: parallel, 16 GB: -j2, below: -j1 (full table in the Build guide).
  • Run only the provided worlds; prefer headless:=true when iterating.
  • Before launching Gazebo, kill any stale gz sim/ruby processes.

Network layout

All robot hardware sits on the 192.168.100.0/24 subnet. The robot PC needs a static address on that subnet (e.g. 192.168.100.x) to reach the LiDARs and the motor/IO controller.

192.168.100.100  motor controller (:23) + IO board (:26)
192.168.100.101  forward LiDAR (UDP 502 -> host 6667)
192.168.100.102  rear LiDAR    (UDP 502 -> host 6668)
