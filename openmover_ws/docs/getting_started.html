Requirements

RequirementMinimum / recommended
Operating systemUbuntu 24.04 LTS (Noble). This is the only distribution supported by ROS 2 Jazzy binaries.
CPUx86_64 multi-core (4 cores or more recommended).
RAM16 GB recommended. Less is possible but requires lower build parallelism; the simulation + rviz + Gazebo together approach ~10 GB at runtime. See the Build guide for per-memory settings.
GPUAny OpenGL 3.3+ GPU for the Gazebo GUI; a discrete GPU keeps rendering smooth. Headless/server mode needs no display.
Disk~10 GB for ROS 2 + Gazebo, plus ~2–3 GB for the workspace build artifacts.
ROS distributionROS 2 Jazzy Jalisco (desktop or base + extras).
SimulatorGazebo Harmonic (gz sim 8.x), shipped as ros-jazzy-ros-gz.
PythonPython 3.12 (system default on 24.04).
Memory

A full-parallel colcon build can exhaust memory and hard-freeze a 16 GB machine. The build commands in this guide therefore use 2 workers — keep that limit unless you have 32 GB or more (Build guide).

Shortcut

Instead of the manual steps below you can run the interactive setup wizard:

bash tools/setup.sh

It detects your system, tells you whether it is sufficient, picks a safe build parallelism for your RAM, and offers to install dependencies, build the workspace and run the tests. bash tools/setup.sh --check performs the detection only.

1. Operating system

Install Ubuntu 24.04 LTS and update it:

sudo apt update && sudo apt upgrade -y
sudo apt install -y curl gnupg lsb-release software-properties-common git build-essential

2. Install ROS 2 Jazzy

Follow the official debian-based install. Summary:

# 1. locale
sudo apt install -y locales
sudo locale-gen en_US en_US.UTF-8 && sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8

# 2. enable the ROS 2 apt repository
sudo apt install -y software-properties-common
sudo add-apt-repository universe
sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
     -o /usr/share/keyrings/ros-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] \
     http://packages.ros.org/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" | \
     sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null

# 3. install ROS 2 Jazzy desktop + the tools this project needs
sudo apt update && sudo apt upgrade -y
sudo apt install -y ros-jazzy-desktop \
     ros-dev-tools python3-colcon-common-extensions

# 4. environment (add to ~/.bashrc to make permanent)
source /opt/ros/jazzy/setup.bash

3. Install Gazebo Harmonic

Gazebo Harmonic is provided as ROS packages, so it comes with the Jazzy repos:

sudo apt install -y ros-jazzy-ros-gz
# verify
gz sim --versions   # should print 8.x (Harmonic)

4. Install dependencies

These ROS/system packages are required by the workspace. Install them up front, or let rosdep resolve them in the next step:

sudo apt install -y \
    ros-jazzy-cartographer-ros ros-jazzy-cartographer-ros-msgs \
    ros-jazzy-nav2-costmap-2d ros-jazzy-nav2-map-server \
    ros-jazzy-nav2-lifecycle-manager ros-jazzy-nav2-msgs \
    ros-jazzy-nav2-bringup ros-jazzy-navigation2 \
    ros-jazzy-slam-toolbox \
    ros-jazzy-laser-geometry ros-jazzy-pcl-ros ros-jazzy-pointcloud-to-laserscan \
    ros-jazzy-robot-state-publisher ros-jazzy-xacro \
    ros-jazzy-joint-state-publisher ros-jazzy-teleop-twist-keyboard \
    ros-jazzy-rosbridge-server ros-jazzy-joy ros-jazzy-tf-transformations \
    ros-jazzy-ros-gz-sim ros-jazzy-ros-gz-bridge \
    ros-jazzy-rviz2 \
    libpcl-dev libeigen3-dev libopencv-dev libyaml-cpp-dev libboost-dev \
    python3-pynput python3-pygame

Then run rosdep over the workspace to catch anything missed:

sudo rosdep init || true
rosdep update
cd ~/openmover_ws      # path to this workspace
rosdep install --from-paths src --ignore-src -r -y --rosdistro jazzy
Note

libosqp-dev is not available in the Ubuntu 24.04 apt repositories, so OSQP is built from source in the next step.

5. Build & install OSQP

OSQP is the QP solver used by the path smoothers. It is vendored in the ROS 1 repo and must be compiled into /usr/local (the same as the original install.sh did):

sudo apt install -y cmake ninja-build
# OSQP source lives under tools/ in this workspace
cd ~/openmover_ws/tools/osqp_build   # or the vendored openmover_robot/osqp
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
sudo cmake --install build
# verify
ls /usr/local/lib/libosqp.* /usr/local/include/osqp

6. Get the workspace

Copy or clone this workspace so the layout below exists. Only src/ is needed to build; build/, install/, and log/ are regenerated.

openmover_ws/
├── src/
│   ├── openmover_msgs/
│   ├── openmover/
│   ├── auto_mapping_toolbox/   # contains auto_mapping_toolbox_msgs too
│   ├── relocalization_toolbox/ # contains relocalization_toolbox_msgs too
│   ├── bluesea2/
│   ├── ira_laser_tools/
│   └── warehouse_simulation/
└── tools/

7. Build the workspace

Source ROS first, then build with the 2-way parallelism limit. The --symlink-install flag means Python/launch/yaml/URDF edits take effect without a rebuild; C++ changes still need a rebuild.

source /opt/ros/jazzy/setup.bash
cd ~/openmover_ws
MAKEFLAGS="-j2" CMAKE_BUILD_PARALLEL_LEVEL=2 \
     colcon build --symlink-install --parallel-workers 2
Tip

Build only what changed to save time, e.g. after editing the relocalization toolbox:

MAKEFLAGS="-j2" CMAKE_BUILD_PARALLEL_LEVEL=2 colcon build --symlink-install --parallel-workers 2 --packages-select relocalization_toolbox

Source the workspace overlay before running anything:

source ~/openmover_ws/install/setup.bash

Run the tests to confirm the build is healthy (fast, no simulation started):

colcon test --packages-select warehouse_simulation --parallel-workers 2
colcon test-result --verbose

8. First run — warehouse simulation

The quickest way to see everything working is the warehouse demo:

# terminal 1 — simulation + Nav2 + slam_toolbox + rviz2
source /opt/ros/jazzy/setup.bash && source ~/openmover_ws/install/setup.bash
ros2 launch warehouse_simulation warehouse_simulation.launch.py

# terminal 2 — keyboard teleop
source ~/openmover_ws/install/setup.bash
ros2 run warehouse_simulation key_control

Drive the Pioneer3DX around; slam_toolbox builds the map and Nav2 plans. To send a navigation goal, use the 2D Goal Pose tool in rviz2. Full walkthrough: Usage.

9. Helper scripts

Three convenience scripts live in the tools directory:

  • tools/setup.sh — interactive setup wizard: detects the system, judges whether it is sufficient, picks a RAM-safe build parallelism, and can install dependencies, build, and test in one guided session (--check for detection only).
  • tools/check_system.sh — read-only health check: verifies OS, ROS, Gazebo, dependencies, OSQP, GPU, and free memory, and prints a PASS/WARN/FAIL summary.
  • tools/install_deps.sh — installs the apt + rosdep dependencies listed above (plus OSQP if missing).

Troubleshooting

SymptomCause / fix
colcon build is killed or the machine freezes Out of memory. Rebuild with --parallel-workers 1 and close other applications. Never run a full-parallel build on 16 GB.
gz sim shows a stale/old world after relaunch A previous server survived and the new client attached to it. Kill leftovers: pkill -f "gz sim"; pkill -f ruby, confirm with ps aux | grep gz, then relaunch.
libosqp not found while linking OSQP was not installed. Repeat step 5 and confirm the files exist in /usr/local/lib.
Robot doesn't move / no map in rviz Check you sourced install/setup.bash and that use_sim_time is consistent. See Usage.
colcon test fails on config YAML The bridge/nav2 configs were edited; see Audit for the validated parameter sets.
